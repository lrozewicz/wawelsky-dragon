# Część core

Inwentaryzacja fragmentów rdzenia (prompty, domena, parsowanie, front) potwierdzonych porównaniem
z upstream RAGFlow `v0.27.2` (kilka fragmentów deklaruje źródło `v0.27.0` — weryfikowane na tym samym
pliku, tag `v0.27.2`, o ile nie zaznaczono inaczej). Metoda: `git -C /host/.../ragflow show <tag>:<ścieżka>`
+ `diff`. Upstream: InfiniFlow, Apache-2.0.

Konwencje ścieżek upstream: `<tag>:<ścieżka>:<linie>`. „Źródło w kodzie” = istniejący komentarz/odwołanie.

## ODRZUCONE

- `backend/app/domain/chat/events.py` — czyste dataclassy zdarzeń WD (ThinkStart/Delta/End, AnswerDelta), brak odpowiednika w upstream.
- `backend/app/domain/chat/kb_text.py` — konwersja HTML→tekst na stdlib `html.parser`; komentarz „jak upstream” dotyczy tylko faktu, że tabele zostają HTML, implementacja własna (upstream `kb_prompt` używa `content` bez konwersji HTML).

- `backend/app/parsing/html.py` — sanityzacja na `lxml` z whitelistą z kontraktu 05 §7; nagłówek „własna implementacja”.
- `backend/app/parsing/blocks.py`, `table_grid.py`, `otsl.py`, `recognizers.py`, `pdf_router.py`, `registry.py`, `diacritics*.py`, `encoding.py`, `errors.py`, `types.py` — parsowanie WD na kontraktach 05/K5; OTSL (`<fcel>` itd.) nie występuje w upstream (`git grep fcel/OTSL` puste); format `positions` `[strona, lewo, prawo, góra, dół]` w `blocks.py` to zgodność z API, nie kopia kodu.
