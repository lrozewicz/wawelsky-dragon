## §1 Dane — bez nowej migracji
Tabele `files` i `file2document` istnieją od `0001` (DDL tam jest źródłem prawdy; K2). Migracja RAGFlow (E4-6b1) wypełnia je już dziś: root użytkownika = wiersz `parent_id IS NULL`, `name='/'`, `type='folder'`; pliki-widoki datasetów RAGFlow mają `source_type='knowledgebase'`.
1. **Root**: jeden wiersz na `tenant_id` (`parent_id NULL`, `name '/'`, `type 'folder'`, `location NULL`, `source_type 'local'`), tworzony **leniwie** przy pierwszym użyciu menedżera plików przez tego użytkownika. Unikat `(tenant_id, parent_id, name)` nie chroni `NULL` w MariaDB → tworzenie roota pod blokadą (`SELECT … FROM users WHERE id=:tenant FOR UPDATE` w tej samej transakcji, potem ponowny odczyt). Id roota zwracane jako `root_folder`/`parent_id` jak w złocie. Upstream ma `parent_id == id` dla roota — WD trzyma `NULL`, prezenter zwraca `parent_id` = id roota (jak upstream).
2. **`.knowledgebase` i pliki-widoki**: WD **nie** odwzorowuje dokumentów datasetów w menedżerze plików (bez folderu `.knowledgebase`, bez wierszy przy uploadzie do datasetu). Wiersze `source_type='knowledgebase'` (z migracji) są **niewidoczne** dla wszystkich tras K16 (listing ich pomija, operacje na nich = „nie znaleziono”). Trwała odchyłka (listing roota `files--05`/`--25` i legacy `--05` bez `.knowledgebase`) → DEC + `deviations/*.yaml`.
3. **Bloby**: plik z menedżera = `filemanager_key(file_id, suffix)` (`backend/app/storage/keys.py`, już używany przez `/documents/upload`); `files.location` = ten klucz. Folder: `location NULL`, `size 0`. **Prezenter** zwraca pola jak złoto, nie wartości kolumn: `location` = nazwa pliku jak upstream (`files--05`: `"ragflow_intro.txt"`, folder `""`), `source_type` `'local'` → `""`, `has_child_folder` tylko dla folderów, `kbs_info`, `parent_id` roota.
4. **Linkowanie do datasetu** (`link-to-datasets`, legacy `convert`): dokument w datasecie z `documents.location` = **ten sam** klucz bloba pliku (bez kopii) + wiersz `file2document`; ingest jak dla uploadu (parse wg ustawień datasetu, jak upstream). Semantyka `mode` (`replace` domyślnie / `add`), rozwijanie folderów do plików, kolejność walidacji i komunikaty — **dosłownie upstream** `file2document_api.py:98+` (v0.27.2 wykonuje w tle i zwraca `data:true` — WD może wykonać synchronicznie w żądaniu, wynik i skutek jak złoto `files--15/16`).
5. **Własność blobów (wiążące)**: blob pod `filemanager/` należy do wiersza `files`. Usunięcie dokumentu (trasy datasetów, czyszczenie ingestii — `backend/app/services/ingest.py` usuwa dziś `doc.location`) **nie usuwa** bloba, którego klucz zaczyna się od `filemanager/`; usuwa tylko link `file2document` (FK CASCADE). Usunięcie pliku (`DELETE /files`, legacy `rm`) usuwa — jak upstream `file_api_service._delete_single_file` — dokumenty z nim zlinkowane (przez usługę dokumentów: chunki, wektory, obrazy), potem wiersz i blob. Folder — rekurencyjnie.
6. `type` pliku i `size` — reguły upstream (`FileService`/`filename_type`); `size` dla uploadu wg złota (uwaga: `/documents/upload` liczy `sys.getsizeof` — sprawdź, którą regułę ma złoto `files--04`, nie zakładaj).
