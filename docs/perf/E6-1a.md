## Werdykt

| Pytanie | Wynik |
|---|---|
| p95 `GET /api/v1/datasets/{id}/documents?metadata_condition=…` (filtr manual, 2 warunki) ≤ 200 ms przy 10 000 dokumentów w jednym datasecie | **NIE** — p95 = **643,9 ms** (min 390,4 / p50 427,9 / max 647,1 ms); ok. **3,2×** powyżej budżetu |

Zgodnie z briefem T6 („jeśli pomiar > 200 ms: STOP, raport BLOCKED z liczbą") **niczego nie
naprawiano** — nie zmieniono `backend/app/**`. Wniosek (pushdown `JSON_EXTRACT`, DEC-300) należy
do osobnego zadania.

## Komenda (powtarzalność)

```bash
tools/perf/meta-filter-10k.sh        # rc != 0 przy p95 > --budget-ms (dom. 200)
```

Skrypt `tools/perf/meta-filter-10k.sh` startuje izolowany stos testowy
(`eval "$(tools/dev/up.sh test env)"`; `tools/dev/up.sh test up mariadb-test migrate api`),
uruchamia CLI `wdperf.meta_filter` (z `backend/`, `PYTHONPATH=../tools/perf:.`) i ZDEJMUJE stos
(`tools/dev/up.sh test down`). Parametry CLI: `--documents 10000 --samples 20 --warmup 3
--page-size 30 --budget-ms 200`; wynik JSON: `tools/perf/out/meta-filter-10k.json` (gitignored).

Parametry biegu: 1 dataset (`perf-meta-10k`, `fake-embed-1024@fake`), 10 000 wierszy `documents`
z `meta_fields ≈ {author, year, topic, note}` (seed bez parsowania — bez chunków i wektorów),
filtr `author = "Adam Kowalski"` AND `year = "2020"` (wartości rozłożone tak, że trafia w ≈ 1,7%).
Metoda: 3 próby rozgrzewki (odrzucone) + 20 prób; czas = `perf_counter` wokół całego żądania HTTP
(do przeczytania odpowiedzi z `total`).

## Charakterystyka (skąd ta liczba)

Zmierzona jest **cała** ścieżka HTTP listy z filtrem. Kod trasy
(`backend/app/services/documents.py::list`): przy `metadata_condition` jedno zapytanie
`documents_query.meta_fields_by_document` wczytuje `meta_fields` **wszystkich** dokumentów datasetu,
dopasowanie liczy `app/domain/retrieval/metadata.py::match_documents` w Pythonie (10 000 × 2 filtry),
a zbiór dopuszczonych id (167) wchodzi do zapytania i licznika jako `CAST(d.id AS BINARY) IN (…)`.
Koszt rośnie liniowo z liczbą dokumentów — dlatego 10k daje setki ms. Przy 1k byłby rzędu kilkudziesięciu ms.

## Ograniczenia

- Stos testowy (jeden `mariadb-test` w kontenerze, pula InnoDB domyślna obrazu testowego); maszyna
  współdzielona z innymi zespołami agentów (obciążenie zmienne, nie mierzone w tym biegu).
- Dane syntetyczne: `meta_fields` bez prawdziwej wariancji wartości; istotny jest rozmiar zbioru
  (10k) i kształt filtra, a nie treść.
- Pomiar end-to-end przez HTTP (z narzutem API/DB), nie mikrobench funkcji `match_documents`.
